# M0 — метаданные записи

Перед записью доступны явные поля: камера, ракурс (сбоку / спереди / под 45°), сторона телефона, ведущая рука и два ручных счёта (с паузами + серия). Отдельного выбора типа замахов нет: заполненные поля ручного счёта описывают состав ролика. `expected_swings` равен сумме введённых чисел; если числа не вводились, это поле `null`.

Невыбранные камера, ракурс, сторона и ведущая рука сериализуются как `unspecified`. Приложение не подставляет `side`, правую руку или тыловую камеру в metadata. Для фактической записи выбор камеры обязателен, чтобы не было неизвестного источника видео.

Для трёх существующих эталонных CSV metadata дополнены: `camera=rear`, `recording_angle=angle_45`, `phone_side=unspecified`, `leading_hand=right`, `expected_swings=8/6/10`.

На Samsung SM-S931B записаны и проанализированы новые ролики с `camera=selfie`: спереди, справа сбоку и под 45°. Их metadata содержат выбранные камеру, ракурс, сторону (где она была введена), ведущую руку, разрешение 1280×720, поворот 270° и конфигурацию фильтров. Ручной счёт в этих трёх исходных metadata не был введён на телефоне; для компьютерных регрессий он добавлен только в локальные test resources по отметкам владельца.

Экран записи прокручивается, кнопка старта расположена до нативного предпросмотра камеры, а `keepScreenOn` включается на время открытого экрана записи. Сборка с этим изменением установлена на телефон; длительная проверка фактического отсутствия блокировки экрана ещё не выполнялась.

Офлайн-анализ не сохраняет экранный статус при блокировке телефона: один из запусков завершил CSV и metadata, но после разблокировки результат не показался. Это зафиксировано как открытое решение в SPEC.md; повторно тот ролик запускать не потребовалось.

# Диагностические скрипты

Записи и экспорты в `data/` в git не попадают, скрипты в этой папке — попадают. Все команды запускаются из корня репозитория.

## Подготовка

```bash
python3 -m venv .venv-diag && .venv-diag/bin/pip install -r data/scripts/requirements.txt
```

Для работы с телефоном нужен `adb` (Android platform-tools), для кадров из видео — `ffmpeg`.

## Скрипты

| Скрипт | Что делает |
|---|---|
| `pull_recordings.sh` | Забирает с телефона новые видео, CSV точек, metadata и CSV замахов в `data/`. Повторно не скачивает (файл, переименованный с меткой вроде `-4-5-front`, тоже считается скачанным). CSV точек без metadata пропускает: анализ ещё идёт. `--list` — только показать файлы на телефоне. |
| `check_segmentation.py` | Эталонная сегментация (`swing_segmentation_reference.py` в корне). Без аргументов — все размеченные ролики из `app/src/test/resources`: счёт по умолчанию и матрица параметров. С путями к CSV — окна замахов этих файлов. |
| `plot_coordinate.py` | График координаты замаха с порогами и окнами (засчитанные — оранжевые, остальные — серые) и размера торса в кадре. |
| `swing_features.py` | Признаки каждого окна замаха: подъём руки, отведение назад, разворот плеч, разворот плеч относительно таза. Так найдено правило «неполный замах». |
| `contact_sheet.sh` | Кадры видео одной картинкой — проверить ручной счёт или момент. |
| `adb_ui.sh` | Управление приложением на телефоне для проверок: `dump`, `tap "<текст>"`, `screenshot`, `start`. Пока открыто «Зеркало», `dump` не работает (превью камеры). |

## Как добавить ролик в автотесты

1. Снять на телефоне, проанализировать в приложении (в блоке «Для диагностики» можно сразу ввести ручной счёт).
2. `data/scripts/pull_recordings.sh`.
3. Проверить: `.venv-diag/bin/python -I data/scripts/check_segmentation.py data/landmarks_<id>.csv`.
4. Скопировать `landmarks_<id>.csv` и `.metadata.json` (с `expected_swings` и `manual_counts`) в `app/src/test/resources/m3/` — ролик автоматически войдёт во все тесты счёта и устойчивости.
